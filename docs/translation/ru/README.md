**Менеджер управления TAILSCALE со встроенным межсетевым экраном для FUNNEL**

**OMEGA-TAIL** — это TUI-приложение (Terminal User Interface) на Python, построенное на
[Textual](https://textual.textualize.io/). Оно позволяет управлять **Tailscale** и тонко настраивать его в
расширенном режиме из интерфейса, не запоминая ни одной команды. Кроме того, оно добавляет средства защиты
(межсетевой экран, ограничение ресурсов, живучесть…) для режима **Funnel**, который открывает службу машины для
всего Интернета.

Каждое действие, изменяющее машину, сначала показывает свою команду. Пароль sudo вводится в терминале, действие за
действием, и ничего не запускается в фоне без вашего ведома.

## Обзор

### Зачем нужен omega-tail

Tailscale Funnel публикует службу машины в Интернете, не открывая порт на роутере: посетители проходят через
ретрансляторы Tailscale. Со стороны сети это просто и надёжно, но одна слабость остаётся.

- **Стоимость шифрования.** В режиме Funnel по умолчанию TLS-рукопожатие каждого посетителя выполняет служба
  `tailscaled` на машине. По измерениям на небольшой машине это около **80 % стоимости соединения**. Нескольких
  сотен новых соединений в секунду достаточно, чтобы полностью загрузить процессор: один обычный компьютер с
  простым скриптом может положить и сайт, и машину.
- **Невидимые посетители.** Обычные межсетевые экраны (nftables, ufw, fail2ban) не видят этих посетителей: они
  приходят зашифрованными, через туннель Tailscale, с адресом ретранслятора.
- **Разрозненные настройки.** Настроек Tailscale (оператор, выходной узел, маршруты, SSH, щит…) много, они
  распределены между командами и веб-консолью, а некоторые могут оборвать текущий сеанс.

### Цели

- Полностью управлять Tailscale из интерфейса, с поясняющей фразой для каждой настройки.
- Отклонять злоупотребляющие соединения **до** любого шифрования, видя реальный адрес каждого посетителя.
- Сохранять машину работоспособной под атакой: администрирование и другие службы остаются доступными.
- Ничего не навязывать: предлагать, показывать команду, спрашивать и иметь возможность откатиться.
- Работать в любом дистрибутиве Linux, под systemd, OpenRC или runit.

### Что делает omega-tail

- Показывает состояние Tailscale, машины и того, что опубликовано, с предупреждениями, ведущими на экран, где
  можно всё исправить.
- Запускает, останавливает и перезапускает `tailscaled`, с защитой от ошибки, если ваш сеанс идёт через
  Tailscale.
- Управляет подключением, учётными записями и всеми настройками `tailscale set`, проверяемыми перед применением.
- Публикует, снимает с публикации, приостанавливает и проверяет службы Serve и Funnel, с резервными копиями и
  восстановлением.
- Показывает устройства tailnet, их путь (прямой или через ретранслятор), диагностику сети и журналы.
- Ставит **шлюз** HAProxy между Funnel и вашим сайтом: правила по адресу, по префиксу, общий бюджет, список
  доверенных и чёрный список, группировка по отпечатку JA4, сети происхождения (AS) и стране, автоматический режим
  атаки.
- Ограничивает ресурсы `tailscaled`, отключает Funnel на время или полностью и может делать это сам благодаря
  автоматическому надзору.
- Защищает порт WireGuard службы `tailscaled` таблицей nftables (щит).
- Формирует отчёт о машине и об атаках за последние 7 дней в форматах TXT, HTML или JSON.

### Чего проект не делает

- Не заменяет Tailscale: он им управляет.
- Не защищает от объёмной атаки, которая забивает само интернет-подключение (роутер, канал).
- Не управляет веб-консолью администрирования Tailscale (политика доступа, одобрение выходных узлов, включение
  Funnel для tailnet).
- Не защищает службу, опубликованную иначе, чем через Funnel: для таких портов есть omega-fire.
- Никогда не работает от root и ничего не запускает в фоне без вашего согласия.
- Не работает ни в Windows, ни в macOS.

## Понимание Tailscale и Funnel

omega-tail предполагает знание нескольких понятий Tailscale. Этот раздел собирает их, не предполагая ничего
другого.

### Словарь

| Термин | Что это такое |
|---|---|
| **Tailnet** | Ваша частная сеть Tailscale: все машины, подключённые к одной учётной записи (или одной организации). Каждая машина получает в ней адрес `100.x.y.z` (диапазон 100.64.0.0/10) и адрес IPv6 в `fd7a:115c:a1e0::/48`. |
| **`tailscaled`** | Служба (демон), работающая на машине: она держит зашифрованный туннель WireGuard, сетевой стек Tailscale и, для Serve и Funnel, ретрансляцию к вашим службам. |
| **`tailscale`** | Команда, управляющая `tailscaled` (`tailscale status`, `tailscale set`, `tailscale funnel`…). omega-tail использует её за вас. |
| **WireGuard** | Протокол зашифрованного туннеля между машинами. Для этого `tailscaled` слушает UDP-порт (по умолчанию 41641), который часто открывает роутер (UPnP). |
| **Ретранслятор DERP** (DERP relay) | Серверы Tailscale, которые ретранслируют трафик, когда две машины не могут связаться напрямую (сложный NAT). «Прямой» путь быстрее. |
| **MagicDNS** | Имена машин tailnet в виде `machine.nom-du-tailnet.ts.net`. |
| **Serve** | Публикация локальной службы (сайта, API…) **только для tailnet**, по HTTPS с действительным сертификатом `*.ts.net`. |
| **Funnel** | Публикация локальной службы **для всего Интернета** по адресу `https://machine.nom-du-tailnet.ts.net`. Открыть можно только порты 443, 8443 и 10000. |
| **Ретранслятор Funnel** (Funnel relay) | Серверы Tailscale, которые принимают посетителей из Интернета и вводят их в ваш tailnet (они видны как «funnel-ingress-node»). |
| **Оператор** | Учётная запись Linux, которой разрешено настраивать Tailscale без sudo (`tailscale set --operator=…`). omega-tail предлагает это один раз, через sudo. |
| **Выходной узел** (exit node) | Машина tailnet, через которую другая машина пропускает весь свой интернет-трафик (как VPN). Её нужно одобрить в консоли Tailscale. |
| **Анонсируемая подсеть** (subnet router) | Локальная сеть (например, `192.168.1.0/24`), которую машина делает доступной для остального tailnet. |
| **Щит** (shields up) | Настройка Tailscale, отклоняющая все входящие соединения из tailnet. |
| **SSH Tailscale** | SSH-сервер, предоставляемый Tailscale и разрешаемый политикой tailnet. |
| **Заголовок PROXY v2** | Короткий заголовок в начале соединения, передающий реальный адрес посетителя тому, кто это соединение принимает. |
| **Отпечаток JA4** (JA4 fingerprint) | Сигнатура того, как программа открывает TLS-соединение: у браузера и у инструмента атаки она разная. |
| **AS (автономная система)** | Сеть происхождения адреса: интернет-провайдер, хостинг, облако. |

### Путь посетителя

**Funnel по умолчанию, без omega-tail.** `tailscaled` делает всё: расшифровывает туннель WireGuard, выполняет
TLS-рукопожатие посетителя, затем ретранслирует запрос по HTTP на ваш сайт. Ни один межсетевой экран машины не
видит посетителя, а каждое новое соединение дорого обходится `tailscaled`.

```text
Посетитель ──HTTPS──▶ Ретранслятор Funnel ──WireGuard──▶ tailscaled (TLS + ретрансляция HTTP) ──HTTP──▶ ваш сайт
                      (Tailscale)                        └── все затраты здесь
```

**Funnel со шлюзом omega-tail.** Funnel переходит в режим TCP: `tailscaled` больше не выполняет TLS, а передаёт
ещё зашифрованный поток шлюзу, предваряя его реальным адресом посетителя (заголовок PROXY v2). Шлюз принимает
решение **до** любого шифрования: отклонённое соединение почти ничего не стоит, а расшифровываются только
допущенные соединения — с помощью OpenSSL, который быстрее TLS в `tailscaled`.

```text
Посетитель ──HTTPS──▶ Ретранслятор Funnel ──WireGuard──▶ tailscaled (TCP + PROXY v2)
                                                              │
                                                              ▼
                                               Шлюз omega-tail (HAProxy, 127.0.0.1)
                                               ├── отказ до TLS: чёрный список, частота, бюджет, целевое имя, группировка
                                               └── допущено: TLS (сертификат *.ts.net) ──HTTP──▶ ваш сайт
```

Шлюз слушает только локальную петлю машины и работает от вашей учётной записи. Машины вашего tailnet допускаются
всегда, до любого правила: фильтруются только посетители Funnel.

### Что должен разрешать Tailscale (консоль администрирования)

Эти настройки делаются один раз, в веб-консоли Tailscale; omega-tail их не меняет.

- **MagicDNS** и **сертификаты HTTPS** включены для tailnet (нужны для Serve, Funnel и сертификата шлюза).
- **Funnel разрешён** для машины в политике доступа tailnet (атрибут `funnel`).
- Для выходного узла или анонсируемых подсетей: их **одобрение** в консоли.

## Возможности

Главное меню состоит из двух колонок по шесть пунктов: **TAILSCALE** для управления, **ЗАЩИТА** для обороны.

### TAILSCALE

#### 1. Панель мониторинга

- **Tailscale**: служба, состояние подключения, работающая и установленная версии, имя машины, адреса, учётная
  запись, устройства в сети, истечение срока ключа, оператор, предлагаемый и используемый выходной узел,
  анонсируемые подсети.
- **Машина**: CPU всей машины, нагрузка на ядро, температура, память, CPU и память `tailscaled`, ограничение
  ресурсов, затем состояние средств защиты (Funnel, межсетевой экран и режим атаки, чёрный список, надзор, щит).
- **Публикация**: каждый опубликованный порт, для Интернета (Funnel) или для tailnet (Serve), его режим и цель.
- **Предупреждения**, от самого серьёзного к наименее серьёзному, с кнопкой «Исправить», открывающей нужный экран.
  Например: служба остановлена, обновление установлено, но не применено, ключ скоро истекает, Funnel опубликован
  без защиты, высокая температура, `tailscaled` слишком прожорлив или не ограничен, чёрный список растёт.
- Значения зелёным, оранжевым или красным цветом по порогам (CPU, нагрузка, температура, память, `tailscaled`).

#### 2. Служба tailscaled

- Состояние с точки зрения системы инициализации, работающая и установленная версии, команда запуска, файлы
  дополнений (drop-in), ограничение ресурсов.
- **Запустить**, **Остановить**, **Перезапустить** (например, чтобы применить уже установленное обновление).
- **Защита от ошибки**: если ваш сеанс идёт через Tailscale (SSH через tailnet), «Остановить» требует второго
  подтверждения, потому что вы больше не сможете перезапустить службу.
- **Исправить запуск**: находит файл дополнения, который запускает `tailscale up` при старте и рискует вывести
  машину из tailnet при первом же изменении настроек; исправление показывается, а оригинал сохраняется.

#### 3. Подключение и настройки

- **Войти**, **Выйти**, **Добавить учётную запись**, **Сменить учётную запись**, **Окончательный выход** (нужно
  ввести имя машины).
- **Все настройки `tailscale set`**, каждая с поясняющей фразой: имя и псевдоним машины, маршруты, DNS tailnet,
  щит, фильтрация с отслеживанием состояния, режим netfilter, выходной узел, доступ к локальной сети, предложение
  машины в качестве выходного узла, анонсируемые подсети, SSH Tailscale, веб-интерфейс, обновления, ретранслятор
  между узлами (peer relay), оператор.
- Во время ввода рамка показывает **до → после** и команду; после применения каждое перечитанное значение
  помечается ✔ (принято) или ✖ (нет).
- Предупреждение сообщает, когда изменение может оборвать сеанс, идущий через Tailscale.
- **Пересылка IP**: включается одной кнопкой, когда машина служит выходным узлом или анонсирует подсети.

#### 4. Публикация

- Всё, что публикует машина: порт, публично (Funnel) или в tailnet (Serve), режим, путь, цель, защита.
- **Опубликовать** локальную службу по HTTPS, HTTP, TCP или с терминацией TLS; **Снять**; **Приостановить
  Funnel** и **Восстановить Funnel** (в точности как было).
- **Сквозная проверка**: настоящее соединение, как у посетителя (ответ, время, сертификат, версия TLS).
- **Резервные копии**: состояние до каждого изменения (50 последних), с возможностью восстановления.
- Каждое изменение проверяется; при расхождении публикация пересобирается, а если это не удаётся, возвращается
  прежнее состояние.

#### 5. Сеть и устройства

- **Устройства** tailnet: система, в сети или нет, путь (прямой или через ретранслятор), когда последний раз был в
  сети, адрес, объём трафика; ретрансляторы Funnel Tailscale по умолчанию скрыты.
- **Ping Tailscale** (путь и задержка), **Кто это?** (кому принадлежит адрес tailnet).
- **Диагностика сети**: UDP, IPv4 / IPv6, тип NAT, открытие портов роутером (UPnP, NAT-PMP, PCP), ближайший
  ретранслятор и задержки.
- **DNS**, **блокировка tailnet** (tailnet lock) и **внутренние счётчики** Tailscale.
- Только чтение: ничто на этом экране не меняет настройки.

#### 6. Журналы

- Журнал `tailscaled` (journalctl или файлы службы вне systemd) и журнал шлюза, с фильтрацией и экспортом.
- У каждого элемента свой цвет, взятый из темы: дата, процесс, категория сообщения (управление, сеть, DNS, движок
  WireGuard), адреса жирным, ошибки красным, предупреждения оранжевым; для шлюза — причина отказа, группировка, AS и
  страна.

### ЗАЩИТА

#### 7. Межсетевой экран Funnel

- **Установить HAProxy** менеджером пакетов дистрибутива (pacman, apt, dnf, zypper, apk, xbps, emerge).
- **Включить защиту**: сертификат `*.ts.net`, списки, проверенная конфигурация, служба шлюза, переключение Funnel,
  затем проверка из Интернета; в случае неудачи исходная публикация сразу же восстанавливается.
- **Отключить защиту**: Funnel возвращается точно в прежнее состояние, с проверкой.
- **Правила**, применяемые на лету, режим **наблюдения**, чтобы без риска подобрать пороги, **группировка** (см.
  [Средства защиты подробно](#средства-защиты-подробно)).
- **Обновить базу** AS / стран (DB-IP Lite), в отдельном процессе.

#### 8. Живучесть

- **Ограничение ресурсов `tailscaled`**: потолок CPU, вес и приоритет, вариант с приоритетом для доступа по SSH.
- **Предохранитель Funnel**: пороги CPU и температуры, отключение на 10 минут (автоматическое восстановление) или
  полное.
- **Автоматический надзор**: то же самое, когда перед экраном никого нет.
- **Щит порта WireGuard**: кнопка, ведущая на его экран (наблюдение, активный, поставить, поставить заново, снять,
  передать).

#### 9. Атаки и решения

- Счётчики шлюза (получено, отклонено до шифрования, допущено, в процессе) и самые активные адреса, обновляемые
  каждые 2 секунды, со страной, AS и состоянием каждого адреса.
- **Заблокировать**, **Чёрный список**, **Разблокировать**, **Доверять**: применяется сразу, без перезапуска
  шлюза; уведомление в одной строке сообщает действие и место адреса.
- Представления **Отпечатки**, **AS** и **Страны**; состояние режима атаки и соединения, отклонённые группировкой.
- **Управление чёрным списком**: полный список с датой добавления и происхождением, добавление, удаление, импорт
  файла TXT (дубликаты, уже охваченные сети и адреса tailnet отбрасываются), очистка с предпросмотром (по
  давности, N самых старых, диапазон строк, происхождение, всё), экспорт в TXT (пригоден для повторного импорта),
  HTML и JSON. Предел — 50 000 записей.

#### 10. Отчёт

- Всё, что omega-tail знает о машине, в виде фактов: Tailscale, публикация, машина, межсетевой экран, живучесть,
  предупреждения и **атаки за последние 7 дней**, прочитанные из журнала шлюза.
- **Конфиденциальность**: по умолчанию без учётной записи Tailscale и без имён и адресов устройств tailnet, чтобы
  отчёт можно было кому-нибудь отправить.
- Экспорт в **TXT**, **HTML** (тема на выбор) и **JSON**; **Показать экспорт** открывает папку в браузере.

#### 11. Настройки

- Язык интерфейса и экспорта, тема интерфейса и экспорта, папки экспорта и снимков экрана, а также их очистка.

#### 12. Справка

- Один раздел на каждый экран, сочетания клавиш, командная строка и **Контакты и поддержка**.

## Средства защиты подробно

Каждое средство защиты отвечает на конкретную угрозу; ни одно не навязывается.

| Защита | От чего | Где |
|---|---|---|
| Шлюз (правила) | Всплески с одного или нескольких адресов, соединения, не адресованные сайту | Межсетевой экран Funnel |
| Группировка | Атаки с рассредоточенных адресов (тысячи адресов, по одному соединению с каждого) | Межсетевой экран Funnel |
| Чёрный список | Адреса и сети, известные атаками, хранимые долгое время | Атаки и решения |
| Ограничение ресурсов | `tailscaled`, который под атакой занял бы всю машину | Живучесть |
| Предохранитель | Машина всё равно перегружена: отключить Funnel на время | Живучесть |
| Автоматический надзор | То же самое, когда перед экраном никого нет | Живучесть |
| Щит WireGuard | Поток UDP-пакетов на порт `tailscaled`, открыт Funnel или нет | Живучесть |

### Шлюз (межсетевой экран Funnel)

Правила применяются в следующем порядке, все до шифрования:

1. **Машины tailnet** (100.64.0.0/10, fd7a:115c:a1e0::/48): допускаются всегда.
2. **Список доверенных**: никогда не ограничивается. **Чёрный список**: отклоняется, пока адрес не удалён из
   списка.
3. **Частота на адрес** (по умолчанию 40 соединений / 10 с): сверх неё адрес блокируется на выбранное время (по
   умолчанию 60 мин).
4. **Частота на префикс** /24 в IPv4, /64 в IPv6.
5. **Общий бюджет** допускаемых соединений в секунду: процессор никогда не перегружается.
6. **Целевое имя**: соединение, не адресованное имени машины, отклоняется.

Сертификат `*.ts.net` шлюза запрашивается у Tailscale, проверяется каждый день и обновляется на лету за 30 дней до
истечения срока. Режим **наблюдения** считает всё, ничего не отклоняя.

### Группировка (отпечатки, AS, страны)

При атаке с рассредоточенных адресов правила по адресу видят каждый адрес лишь один раз. Поэтому шлюз
классифицирует каждого клиента также по его **отпечатку JA4**, **AS** и **стране** и считает частоту соединений
каждой группы.

- **Автоматический режим атаки**: свыше 80 входящих соединений в секунду (настраивается) шлюз сам переходит в
  режим атаки и выходит из него после 5 минут затишья.
- Только в режиме атаки: неизвестный отпечаток, число соединений с которым резко растёт, AS хостинга или облака
  (список изменяемый) или страна из вашего списка (по умолчанию пустого), превысившие свою частоту, отклоняются.
- **Распространённые браузеры** (Chrome, Edge, Firefox) никогда не затрагиваются этими правилами; **известные
  клиенты** (допущенные за последние 24 ч) проходят раньше общего бюджета.
- **Обучение**: в течение 7 дней шлюз изучает обычные отпечатки вашего сайта (никогда во время атаки); до этого
  группировка остаётся в режиме наблюдения.
- Вне атаки классифицируется одно соединение из десяти; во время атаки — все.
- База AS / стран — **DB-IP Lite**, загружается и обновляется раз в месяц.

### Живучесть

- **Ограничение ресурсов**: отдельный файл дополнения ограничивает `tailscaled` (например, одним целым ядром на
  машине с 4 потоками) и понижает его приоритет. Ваша собственная конфигурация никогда не изменяется.
- **Предохранитель**: когда `tailscaled` держится выше порога CPU (по умолчанию 80 % ядра в течение 60 с) или
  температура достигает 85 °C, omega-tail предлагает отключить Funnel на 10 минут (автоматическое восстановление, в
  точности как было, даже при закрытом omega-tail), отключить его полностью или подождать. Tailnet никогда не
  отключается.
- **Автоматический надзор** (по умолчанию выключен): служба под вашей учётной записью сама отключает Funnel после
  трёх превышений — на 15 минут в первый раз, на 30 во второй, затем на час — и сама его восстанавливает.

### Щит порта WireGuard

`tailscaled` тратит около одного ядра процессора на 100 000 пакетов в секунду, полученных на его UDP-порт, даже
недействительных. Щит — это таблица nftables, поставленная перед ним, на сетевых картах:

- **известные узлы** (peers, которым пишет `tailscaled`) никогда не ограничиваются;
- рукопожатия ограничены 20 в секунду на источник;
- у остальных источников есть бюджет (500 пакетов в секунду на каждый, 5 000 всего);
- пакеты, не являющиеся трафиком WireGuard, отклоняются.

Сначала он ставится в режиме **наблюдения**, затем в **активном** режиме. Если машины связаны через omega-connect,
**omega-fire** (3.7.0 или новее) может поставить его и управлять им вместо omega-tail: это та же таблица, которая
меняет владельца, оставаясь нетронутой.

## Измерения

Решения omega-tail основаны на измерениях, сделанных на машинах того же поколения, что и защищаемые (процессоры
2010–2016 годов, в большинстве без аппаратного ускорения AES).

| Измерение | Результат |
|---|---|
| Доля TLS в стоимости соединения при Funnel по умолчанию | около 80 % |
| Стоимость соединения, **отклонённого** шлюзом, по сравнению с Funnel по умолчанию | **в 4,6 раза меньше** |
| Стоимость соединения, **допущенного** шлюзом, по сравнению с Funnel по умолчанию | **в 2 раза меньше** |
| Пропускная способность со шлюзом, соединения держатся открытыми (по сравнению с TLS на Go, как в `tailscaled`) | **+15 %** запросов, −20 % CPU |
| Щит WireGuard: поток, который занимал у `tailscaled` целое ядро | **1 %** ядра |
| Память служб (шлюз, надзор, щит) | около 67 МБ |

Таким образом, шлюз не снижает пропускную способность сайта: на этих машинах ограничивает само шифрование, с
omega-tail или без него, а в рабочей среде Funnel в любом случае проходит через ретрансляторы Tailscale и через
роутер.

## Архитектура

```text
src/omega_tail/
├── app/              Корень композиции: собирает слои, точка входа (интерфейс, командная строка)
├── core/             Общие константы
├── domain/           Чистая бизнес-логика: правила шлюза, предупреждения, предохранитель, надзор, чёрный список…
├── application/      Сценарии использования: публикация, межсетевой экран, живучесть, отчёт, настройки
├── ports/            Контракты (Protocol), ожидаемые приложением
├── infrastructure/   Tailscale, HAProxy, nftables, systemd / OpenRC / runit, журналы, экспорт, скрипты Lua
├── interfaces/       tui/ (Textual), cli/ (командная строка), shared/ (справка, отчёт, представление)
└── shared/           Языки (gettext)
```

### Принципы проектирования

- `domain/` не содержит ни чтения, ни записи: всё в нём тестируется без машины.
- `application/` оркестрирует сценарии использования через домен и порты; интерфейс и командная строка вызывают
  одни и те же сценарии.
- Команды запускают только `infrastructure.commands` и `infrastructure.privileged`; интерфейс никогда не делает
  этого напрямую. Эти правила проверяются автоматически (import-linter).
- Интерфейс опирается на [omega-lib](https://github.com/kraynux), библиотеку, общую для всего пакета OMEGA (темы,
  определение терминала, языки, контакты и поддержка, щит WireGuard). Она не опубликована на PyPI: она встроена в
  архив (`vendor/omega-lib/`).
- Любой медленный вызов (Tailscale, HAProxy, диск, сеть) выполняется в фоновой задаче: интерфейс никогда не
  зависает.

## Требования

### Система

- Linux, любой дистрибутив (проверено на Arch Linux и производных).
- Python 3.10 или новее, с модулем `venv`.
- Система инициализации: **systemd**, **OpenRC** или **runit**.
- `sudo` для действий, изменяющих машину (запрашивается для каждого действия, никогда при запуске).
- Терминал не меньше 80×24 (см. [Темы и терминалы](#темы-и-терминалы)).

### Tailscale

- **Tailscale** установлен и подключён (клиент `tailscale` и служба `tailscaled`); проверено с версией 1.104.
- Для Funnel: MagicDNS, сертификаты HTTPS и Funnel разрешены в консоли Tailscale (см.
  [Что должен разрешать Tailscale](#что-должен-разрешать-tailscale-консоль-администрирования)).

### Зависимости Python

Устанавливаются `install.sh` в виртуальное окружение:

- `textual`: интерфейс.
- `omega-lib`: общая библиотека пакета OMEGA, встроенная в архив.

### Обязательные и опциональные компоненты

omega-tail определяет, что присутствует, и включает только то, чем можно воспользоваться.

| Компонент | Роль | Статус |
|---|---|---|
| Tailscale (`tailscale`, `tailscaled`) | Всё, чем управляет omega-tail | **Обязательно** |
| Python 3.10+, `textual`, `omega-lib` | Приложение | **Обязательно** |
| systemd, OpenRC или runit | Службы шлюза, надзора, щита | **Обязательно** (одна из трёх) |
| HAProxy 3.x | Шлюз межсетевого экрана Funnel | Опционально (устанавливается из omega-tail) |
| HAProxy с Lua | Группировка (отпечатки, AS, страны) | Опционально (так в распространённых дистрибутивах) |
| nftables (ядро с `nft_limit`) | Щит порта WireGuard | Опционально |
| Чтение системного журнала (группа `systemd-journal`, `adm` или `wheel`) | Журналы, отчёт об атаках | Рекомендуется |
| Браузер и рабочий стол | «Показать экспорт» в браузере (иначе просмотр в omega-tail) | Опционально |
| omega-connect | Реестр, синхронизация, обновления пакета | Опционально |
| omega-fire 3.7.0+ | Управление щитом WireGuard из omega-fire | Опционально |

## Установка

Официальный архив поставляется в формате `.tar.gz`. Перед установкой проверьте его целостность с помощью файла
`sha.txt`, опубликованного рядом:

```bash
sha256sum omega-tail-0.7.0.tar.gz
```

> ⚠️ **Эти три метода предназначены для первой установки.** Если `~/omega-tail` уже существует, воспользуйтесь
> разделом [Обновление](#обновление). Никогда не запускайте эти команды повторно изнутри существующей папки
> `omega-tail`: `tar` создал бы вложенную папку `omega-tail/omega-tail/`.

Ни один шаг установки не требует прав root: omega-tail запускается от имени обычного пользователя.

### Метод 1 — установочный скрипт

```bash
[ "$(basename "$PWD")" = "omega-tail" ] && { echo "❌ Похоже, вы уже находитесь внутри папки omega-tail — см. раздел Обновление README." >&2; exit 1; }
[ -d omega-tail ] && echo "ℹ️ Уже распаковано здесь, шаг пропущен." || tar -xzf omega-tail-0.7.0.tar.gz
[ -d ~/omega-tail ] && echo "ℹ️ ~/omega-tail уже существует, перемещение пропущено." || mv omega-tail ~/
cd ~/omega-tail/
chmod +x install.sh
./install.sh
```

Скрипт создаёт виртуальное окружение, устанавливает зависимости (сначала встроенную omega-lib), делает скрипты
запуска исполняемыми, записывает установочный токен, который читает omega-connect, и предлагает алиас
`omega-tail`. Его можно безопасно запускать повторно.

### Метод 2 — устойчивая полная установка

Эту команду можно запускать повторно: она пропускает уже выполненные шаги.

```bash
([ "$(basename "$PWD")" = "omega-tail" ] && { echo "❌ Похоже, вы уже находитесь внутри папки omega-tail — см. раздел Обновление README." >&2; exit 1; }; [ -d ~/omega-tail ] && echo "ℹ️ ~/omega-tail уже существует, распаковка пропущена." || (tar -xzf omega-tail-0.7.0.tar.gz && mv omega-tail ~/)) && cd ~/omega-tail/ && ([ -f .venv/bin/activate ] && echo "ℹ️ .venv уже существует, шаг пропущен." || python3 -m venv .venv) && source .venv/bin/activate && ([ -d vendor/omega-lib ] && pip install -q -e vendor/omega-lib || true) && pip install -q -e . && chmod +x omega-tail.sh install.sh && ./omega-tail.sh synchro jeton > /dev/null && echo "✅ Omega-Tail установлен. Запустите ./omega-tail.sh."
```

### Метод 3 — подробная установка

```bash
# 0. Убедиться, что мы не запускаем это изнутри существующей папки omega-tail
[ "$(basename "$PWD")" = "omega-tail" ] && { echo "❌ Похоже, вы уже находитесь внутри папки omega-tail — см. раздел Обновление README." >&2; exit 1; }

# 1. Распаковать
[ -d omega-tail ] && echo "ℹ️ Уже распаковано здесь, шаг пропущен." || tar -xzf omega-tail-0.7.0.tar.gz

# 2. Переместить в домашнюю папку
[ -d ~/omega-tail ] && echo "ℹ️ ~/omega-tail уже существует, перемещение пропущено." || mv omega-tail ~/

# 3. Войти в проект
cd ~/omega-tail/

# 4. Создать виртуальное окружение
[ -f .venv/bin/activate ] && echo "ℹ️ .venv уже существует, создание пропущено." || python3 -m venv .venv

# 5. Установить зависимости (сначала встроенную omega-lib)
source .venv/bin/activate
[ -d vendor/omega-lib ] && pip install -q -e vendor/omega-lib
pip install -q -e .

# 6. Сделать скрипты запуска исполняемыми
chmod +x omega-tail.sh install.sh

# 7. Записать установочный токен (читается omega-connect; необязательно)
./omega-tail.sh synchro jeton

# 8. Запустить
./omega-tail.sh
```

В Debian, Ubuntu и производных модуль `venv` не всегда устанавливается вместе с Python:
`sudo apt install python3-venv`.

### Обновление

Службы omega-tail (шлюз, надзор) используют файлы из `~/omega-tail/var/`. Поэтому обновление должно **оставлять
эту папку на месте**: архив не содержит `var/` и распаковывается поверх существующей установки.

Из папки, в которой лежит архив, **отличной от `~/omega-tail`**:

```bash
# 1. Сделать резервную копию текущей установки (включая var/)
tar -czf ~/omega-tail-sauvegarde-$(date +%Y%m%d).tar.gz -C ~ omega-tail

# 2. Распаковать новую версию поверх (var/ сохраняется)
tar -xzf omega-tail-0.7.0.tar.gz -C ~/

# 3. Переустановить (зависимости, скрипты запуска, установочный токен)
cd ~/omega-tail
./install.sh

# 4. Снова запустить omega-tail
./omega-tail.sh
```

Если шлюз активен, **Межсетевой экран Funnel → «Применить правила»** пересоздаёт его конфигурацию в новой версии,
на лету. Если автоматический надзор включён, **Живучесть → «Включить надзор»** перезапускает его с новым кодом.
Обновление может выполнить и omega-connect (экран Updater).

### Алиас Bash или Zsh

`install.sh` предлагает алиас. Чтобы добавить его вручную:

```bash
grep -qxF 'alias omega-tail="$HOME/omega-tail/omega-tail.sh"' ~/.bashrc 2>/dev/null || echo 'alias omega-tail="$HOME/omega-tail/omega-tail.sh"' >> ~/.bashrc
grep -qxF 'alias omega-tail="$HOME/omega-tail/omega-tail.sh"' ~/.zshrc 2>/dev/null || echo 'alias omega-tail="$HOME/omega-tail/omega-tail.sh"' >> ~/.zshrc
```

Алиас называется `omega-tail`, а не `tail`, чтобы не перекрывать системную команду `tail`.

## Использование

### Запуск

```bash
cd ~/omega-tail
./omega-tail.sh

# или просто, если алиас был создан:
omega-tail
```

Скрипт запуска не запрашивает повышения прав: omega-tail работает под вашей учётной записью, а sudo запрашивают
только те действия, которым он нужен, в терминале, с заранее показанной командой.

### Рекомендуемые первые шаги

Чтобы защитить сайт, опубликованный через Funnel, в таком порядке:

1. **Панель мониторинга**: прочитайте предупреждения; **Стать оператором** (один раз, через sudo), чтобы настраивать
   Tailscale без sudo.
2. **Живучесть → Применить ограничение**: `tailscaled` больше не сможет занять всю машину.
3. **Публикация**: опубликуйте сайт по **HTTPS на порту 443**, путь `/`, затем выполните **сквозную проверку**.
4. **Межсетевой экран Funnel → Установить HAProxy**, затем **Включить защиту**, сначала в режиме **наблюдения**.
5. Через несколько дней, **Атаки и решения**: если счётчики показывают только злоупотребления, переведите шлюз в
   **обычный** режим.
6. Дайте **группировке** обучаться 7 дней в режиме наблюдения, затем переведите её в режим **применения**.
7. **Живучесть → Щит порта WireGuard**: поставьте в режиме наблюдения, затем переведите в активный.
8. Для машины, за экраном которой никого нет: **Живучесть → Включить надзор**.

17 языков: французский, английский, испанский, португальский (Бразилия), итальянский, немецкий, нидерландский,

- Разово: `OMEGA_TAIL_LANG=en ./omega-tail.sh`.

### Контакты и поддержка

Справка (клавиша `a`) предлагает экран **Контакты и поддержка**:

- *Угостить кофе* (страница PayPal разработчика);
- *Связаться с поддержкой* (адрес электронной почты и форма сайта, показываемые открыто);
- *Зарегистрироваться как пользователь (анонимно)*;
- *Проверить обновления*.

Регистрация добровольна, по умолчанию отключена и отправляется только один раз. Она служит лишь для подсчёта
пользователей и, если вы этого хотите, их континента или страны (закрытые списки, никогда не произвольный текст).
Она отправляет случайно сгенерированный ключ, название программы (`omega-tail`) и её версию — никогда имя, имя
машины, настройку или адрес tailnet. Отозвать её можно в любой момент на том же экране (*Больше не регистрировать
меня*). Проверка обновлений читает только список версий, опубликованных на сайте, и никогда без щелчка.

### Связь с другими инструментами omega

- **omega-connect**: `install.sh` записывает установочный токен (`var/omega-jeton.json`), описывающий инструмент и
  его версию, ничего не выполняя. omega-connect использует его для Реестра, синхронизации, восстановления,
  обновлений и установки. `./omega-tail.sh synchro jeton` перезаписывает его вручную.
- **omega-fire** (3.7.0 или новее), связанный через omega-connect, может поставить щит порта WireGuard и управлять
  им; его список правил показывает щит с происхождением omega-tail.

### Общий сценарий работы

1. Экран запуска, затем главное меню в две колонки (TAILSCALE и ЗАЩИТА).
2. Под заголовком каждого экрана **строка состояния** подытоживает всё: служба, CPU машины и `tailscaled`,
   температура, память, Funnel, межсетевой экран, надзор, подключение. Она обновляется каждые 5 секунд.
3. Каждое действие, изменяющее машину, показывает свою команду, затем запрашивает подтверждение; пароль sudo
   вводится в терминале, после чего интерфейс возвращается.
4. Чувствительные действия (окончательный выход, полная очистка чёрного списка) требуют ввести слово.
5. Результат выводится одной строкой и проверяется по перечитанному состоянию.

### Навигация

- Стрелки вверх / вниз: переход от элемента к элементу (строки таблицы, кнопки).
- Tab / Shift+Tab: переход от одной области экрана к другой.
- Enter или щелчок: активировать выбранную кнопку; в таблице предупреждений — «Исправить».
- `Esc`: вернуться на предыдущий экран (в меню: выход).
- `a`: справка, с любого экрана.
- `s`: настройки, с любого экрана.
- `t`: следующая тема (сохраняется).
- `r`: перерисовать экран, показать размер терминала и перечитать состояние.
- `q`: выход, с подтверждением.
- `Ctrl+P`: команды (тема, снимок экрана в SVG в папку снимков, выход).

## Файлы, службы и совместимость

### В папке omega-tail

Всё состояние omega-tail находится в `~/omega-tail/var/`, пересоздаётся при запуске и никогда не публикуется:

```text
var/
├── settings.json         настройки (язык, темы, папки, пороги, правила шлюза)
├── omega-jeton.json      установочный токен (omega-connect)
├── porte/                конфигурация шлюза, сертификат, список доверенных и чёрный список, база AS / стран
├── veille/               журнал автоматического надзора
├── survie/               оригиналы изменённых файлов, состояние предохранителя
├── funnel/sauvegardes/   публикация до каждого изменения (50 последних)
├── exports/              экспортированные отчёты, журналы и списки
└── screenshots/          снимки экрана (Ctrl+P)
```

### В системе (только если вы включаете соответствующую защиту)

Каждый файл ставится через sudo, с показом команды, и удаляется обратным действием в omega-tail.

| Файл или служба | Ставится действием | Удаляется действием |
|---|---|---|
| Служба `omega-tail-porte` (systemd, OpenRC или runit) и `omega-tail-porte-certificat` (таймер systemd или помеченная строка в вашем crontab) | Включить защиту | Отключить защиту |
| `/etc/systemd/system/tailscaled.service.d/50-omega-tail.conf` (или контрольная группа вне systemd) | Применить ограничение | Снять ограничение |
| Таймеры `omega-tail-retablir-*` (восстановление после отключения) | Предохранитель | Конец отключения |
| Служба `omega-tail-veille` | Включить надзор | Отключить надзор |
| Служба `omega-bouclier-wg`, таблица nftables, `/etc/omega-bouclier-wg/` | Щит: Поставить | Щит: Снять |
| `/etc/sysctl.d/99-omega-tail-forwarding.conf` | Включить пересылку IP | Удаление файла |

Файл `override.conf` службы `tailscaled`, если он существует, никогда не изменяется.

### Системы инициализации

| | systemd | OpenRC | runit |
|---|---|---|---|
| Служба `tailscaled` | `systemctl` | `rc-service` | `sv` |
| Журналы | `journalctl` | файлы службы | `svlogd`, `socklog` |
| Ограничение ресурсов | файл дополнения systemd | контрольная группа (cgroup v2) | контрольная группа (cgroup v2) |
| Временное отключение | таймер systemd | отсоединённый процесс под вашей учётной записью | отсоединённый процесс под вашей учётной записью |
| Шлюз, надзор, щит | службы systemd | службы OpenRC | службы runit |

Вне systemd ограничение через контрольную группу теряется при перезапуске `tailscaled`: тогда предупреждение
предлагает применить его заново.

### IPv4 и IPv6

Шлюз, списки, группировка и щит работают с обоими семействами. Учитываемые префиксы — /24 в IPv4 и /64 в IPv6;
адрес IPv4, увиденный в виде `::ffff:a.b.c.d`, обрабатывается как адрес IPv4.

## Безопасность

omega-tail воздействует на службу, открытую в Интернет; он спроектирован так, чтобы никогда не ухудшать ситуацию.

- **Никогда root**: приложение, шлюз HAProxy и надзор работают под вашей учётной записью; sudo запрашивается только
  для установки или удаления службы, с заранее показанной командой.
- **Закрытые каналы**: административные сокеты шлюза имеют режим 600 в папке 700; синхронизация его таблиц идёт
  через сокет в той же папке.
- **Откат**: каждое переключение Funnel сохраняется в резервной копии, проверяется, а при неудаче возвращается
  прежнее состояние.
- **Сначала наблюдение**: шлюз, группировка и щит ставятся в режиме наблюдения; ничего не отклоняется, пока вы так
  не решите.
- **Tailnet никогда не отключается**: шлюз всегда допускает ваши машины, а предохранитель отключает только Funnel.
- **Проверка входных данных**: до HAProxy доходят только адреса или сети в канонической форме; имена, объявляемые
  машинами tailnet, очищаются перед показом.
- **Аудит**: код прошёл аудит (claude-security, 2026-11-25); 7 найденных замечаний, ни одно из которых не могло
  быть использовано посетителем удалённо, исправлены в тот же день.
- Сначала тестируйте на тестовой машине или в режиме наблюдения и используйте для проверок IPv4 документационные
  сети RFC 5737: `192.0.2.0/24`, `198.51.100.0/24`, `203.0.113.0/24`.

## Состояние проекта

### Рабочие пункты

- Полное управление Tailscale: служба, подключение, настройки, публикация, сеть, журналы.

### Известные ограничения

- Службы под OpenRC и runit покрыты тестами, но ещё не проверены на реальной машине.
- Шлюз защищает Funnel, опубликованный по HTTPS на одном порту, с путём `/`.

- Щит нельзя поставить на ядро, обновлённое без перезагрузки (модули отсутствуют): экран сообщает об этом.
- Атака, забивающая само интернет-подключение, остаётся вне досягаемости инструмента, установленного на машине.
- Пропускная способность сайта, опубликованного через Funnel, по-прежнему ограничена ретрансляторами Tailscale и
  роутером.

## Удаление

Сначала уберите из omega-tail всё, что было поставлено в систему, в таком порядке:

1. **Межсетевой экран Funnel → Отключить защиту** (Funnel возвращается в прежнее состояние).
2. **Живучесть → Отключить надзор**.
3. **Живучесть → Щит порта WireGuard → Снять**.
4. **Живучесть → Снять ограничение**.

Затем удалите папку:

```bash
rm -rf ~/omega-tail
```

Вручную удалите экспорт, размещённый в других местах, алиас `omega-tail` из `~/.bashrc` или `~/.zshrc` и, если вы
её включали, файл `/etc/sysctl.d/99-omega-tail-forwarding.conf`. Право оператора Tailscale снимается командой
`sudo tailscale set --operator=`.

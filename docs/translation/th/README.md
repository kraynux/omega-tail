# 🔒 OMEGA-TAIL

**ตัวควบคุม TAILSCALE พร้อมไฟร์วอลล์ในตัวสำหรับ FUNNEL**

OMEGA-TAIL คือเครื่องมือในชุด OMEGA ที่ใช้ควบคุม **Tailscale** บนเครื่อง และ **ปกป้อง** เครื่องนั้นเมื่อเผยแพร่บริการ
สู่อินเทอร์เน็ตผ่าน **Tailscale Funnel**

**OMEGA-TAIL** เป็นแอปพลิเคชัน TUI (Terminal User Interface) เขียนด้วย Python และสร้างด้วย
[Textual](https://textual.textualize.io/) ช่วยให้จัดการและปรับแต่ง **Tailscale** ในโหมดขั้นสูงได้จากอินเทอร์เฟซเดียว
โดยไม่ต้องจำคำสั่งใดเลย นอกจากนี้ยังเพิ่มการป้องกัน (ไฟร์วอลล์ การจำกัดทรัพยากร การอยู่รอด…) สำหรับโหมด **Funnel**
ซึ่งเปิดบริการของเครื่องให้ทั้งอินเทอร์เน็ตเข้าถึงได้

ทุกการกระทำที่เปลี่ยนแปลงเครื่องจะแสดงคำสั่งของมันก่อนเสมอ รหัสผ่าน sudo ป้อนในเทอร์มินัลทีละการกระทำ
และไม่มีสิ่งใดถูกรันในเบื้องหลังโดยที่คุณไม่รู้

## ภาพรวม

### ทำไมต้อง omega-tail

Tailscale Funnel เผยแพร่บริการของเครื่องสู่อินเทอร์เน็ตโดยไม่ต้องเปิดพอร์ตบนเราเตอร์: ผู้เยี่ยมชมผ่านเข้ามาทางรีเลย์ของ
Tailscale ในด้านเครือข่าย วิธีนี้ง่ายและปลอดภัย แต่ยังมีจุดอ่อนหนึ่งอยู่

- **ต้นทุนของการเข้ารหัส** ในโหมด Funnel เริ่มต้น บริการ `tailscaled` ของเครื่องเองเป็นผู้ทำการจับมือ (handshake) TLS
  กับผู้เยี่ยมชมแต่ละราย จากการวัดบนเครื่องขนาดเล็ก ส่วนนี้คิดเป็นประมาณ **80 % ของต้นทุนการเชื่อมต่อหนึ่งครั้ง**
  การเชื่อมต่อใหม่เพียงไม่กี่ร้อยครั้งต่อวินาทีก็เพียงพอจะทำให้โปรเซสเซอร์อิ่มตัว: คอมพิวเตอร์ธรรมดาเพียงเครื่องเดียว
  กับสคริปต์ง่าย ๆ ก็ทำให้เว็บไซต์และเครื่องล่มได้
- **ผู้เยี่ยมชมที่มองไม่เห็น** ไฟร์วอลล์ทั่วไป (nftables, ufw, fail2ban) มองไม่เห็นผู้เยี่ยมชมเหล่านี้: พวกเขามาถึงในสภาพ
  ที่เข้ารหัสอยู่ ผ่านอุโมงค์ของ Tailscale พร้อมที่อยู่ของรีเลย์
- **การตั้งค่าที่กระจัดกระจาย** การตั้งค่าของ Tailscale (ผู้ควบคุม โหนดทางออก เส้นทาง SSH โล่ป้องกัน…) มีจำนวนมาก
  แบ่งอยู่ระหว่างคำสั่งกับคอนโซลเว็บ และบางอย่างอาจตัดเซสชันที่กำลังใช้อยู่

### เป้าหมาย

- ควบคุม Tailscale ได้ทั้งหมดจากอินเทอร์เฟซ พร้อมประโยคอธิบายสำหรับทุกการตั้งค่า
- ปฏิเสธการเชื่อมต่อที่ใช้งานในทางมิชอบ **ก่อน** การเข้ารหัสใด ๆ โดยเห็นที่อยู่จริงของผู้เยี่ยมชมแต่ละราย
- ทำให้เครื่องยังยืนหยัดได้ขณะถูกโจมตี: การดูแลระบบและบริการอื่น ๆ ยังเข้าถึงได้
- ไม่บังคับสิ่งใดเลย: เสนอ แสดงคำสั่ง ถาม และย้อนกลับได้เสมอ
- ทำงานบนทุกดิสทริบิวชัน Linux ภายใต้ systemd, OpenRC หรือ runit

### สิ่งที่ omega-tail ทำ

- แสดงสถานะของ Tailscale ของเครื่อง และของสิ่งที่เผยแพร่อยู่ พร้อมการแจ้งเตือนที่พาไปยังหน้าจอที่ใช้แก้ไข
- เริ่ม หยุด และรีสตาร์ท `tailscaled` พร้อมกลไกป้องกันหากเซสชันของคุณผ่าน Tailscale
- จัดการการเชื่อมต่อ บัญชี และทุกการตั้งค่าของ `tailscale set` ซึ่งตรวจสอบก่อนนำไปใช้
- เผยแพร่ ถอน พักชั่วคราว และทดสอบบริการของ Serve และ Funnel พร้อมการสำรองและการกู้คืน
- แสดงอุปกรณ์ใน tailnet เส้นทางของอุปกรณ์ (ตรงหรือผ่านรีเลย์) การวินิจฉัยเครือข่าย และล็อก
- วาง **ประตู** HAProxy ไว้ระหว่าง Funnel กับเว็บไซต์ของคุณ: กฎตามที่อยู่ ตามพรีฟิกซ์ งบประมาณรวม รายการที่เชื่อถือ
  และบัญชีดำ การจัดกลุ่มตามลายนิ้วมือ JA4 เครือข่ายต้นทาง (AS) และประเทศ โหมดโจมตีอัตโนมัติ
- จำกัดทรัพยากรของ `tailscaled` ตัด Funnel ชั่วคราวหรือทั้งหมด และทำสิ่งนี้เองได้ด้วยการเฝ้าระวังอัตโนมัติ
- ปกป้องพอร์ต WireGuard ของ `tailscaled` ด้วยตาราง nftables (โล่ป้องกัน)
- สร้างรายงานของเครื่องและการโจมตีในช่วง 7 วันล่าสุด เป็น TXT, HTML หรือ JSON

### สิ่งที่โปรเจกต์ไม่ได้ทำ

- ไม่ได้แทนที่ Tailscale: แต่ควบคุมมัน
- ไม่ป้องกันการโจมตีเชิงปริมาณที่ทำให้สายอินเทอร์เน็ตเองอิ่มตัว (เราเตอร์ ลิงก์)
- ไม่จัดการคอนโซลผู้ดูแลระบบบนเว็บของ Tailscale (นโยบายการเข้าถึง การอนุมัติโหนดทางออก การเปิด Funnel ให้ tailnet)
- ไม่ปกป้องบริการที่เผยแพร่ด้วยวิธีอื่นนอกจาก Funnel: สำหรับพอร์ตเหล่านั้น มี omega-fire
- ไม่เคยรันในฐานะ root และไม่รันสิ่งใดในเบื้องหลังโดยไม่ได้รับความยินยอมจากคุณ
- ไม่ทำงานบน Windows หรือ macOS

## ทำความเข้าใจ Tailscale และ Funnel

omega-tail สันนิษฐานว่าคุณรู้แนวคิดบางอย่างของ Tailscale ส่วนนี้รวบรวมแนวคิดเหล่านั้นไว้ โดยไม่สันนิษฐานอย่างอื่นเพิ่ม

### คำศัพท์

| คำศัพท์ | ความหมาย |
|---|---|
| **Tailnet** | เครือข่ายส่วนตัว Tailscale ของคุณ: ทุกเครื่องที่เชื่อมต่อกับบัญชีเดียวกัน (หรือองค์กรเดียวกัน) แต่ละเครื่องได้รับที่อยู่แบบ `100.x.y.z` (ช่วง 100.64.0.0/10) และที่อยู่ IPv6 ใน `fd7a:115c:a1e0::/48` |
| **`tailscaled`** | บริการ (daemon) ที่ทำงานบนเครื่อง: ดูแลอุโมงค์เข้ารหัส WireGuard สแตกเครือข่ายของ Tailscale และสำหรับ Serve และ Funnel ก็ทำหน้าที่รีเลย์ไปยังบริการของคุณ |
| **`tailscale`** | คำสั่งที่ควบคุม `tailscaled` (`tailscale status`, `tailscale set`, `tailscale funnel`…) omega-tail ใช้คำสั่งนี้แทนคุณ |
| **WireGuard** | โปรโตคอลอุโมงค์เข้ารหัสที่ใช้ระหว่างเครื่อง เพื่อการนี้ `tailscaled` รอรับบนพอร์ต UDP (ค่าเริ่มต้น 41641) ซึ่งเราเตอร์มักเปิดให้ (UPnP) |
| **รีเลย์ DERP (DERP relay)** | เซิร์ฟเวอร์ของ Tailscale ที่ส่งต่อทราฟฟิกเมื่อสองเครื่องติดต่อกันโดยตรงไม่ได้ (NAT ที่ยาก) เส้นทาง « ตรง » เร็วกว่า |
| **MagicDNS** | ชื่อของเครื่องใน tailnet ในรูปแบบ `machine.nom-du-tailnet.ts.net` |
| **Serve** | เผยแพร่บริการภายในเครื่อง (เว็บไซต์ API…) **สำหรับ tailnet เท่านั้น** ผ่าน HTTPS ด้วยใบรับรอง `*.ts.net` ที่ถูกต้อง |
| **Funnel** | เผยแพร่บริการภายในเครื่อง **สำหรับทั้งอินเทอร์เน็ต** ที่ที่อยู่ `https://machine.nom-du-tailnet.ts.net` เปิดได้เฉพาะพอร์ต 443, 8443 และ 10000 |
| **รีเลย์ Funnel (Funnel relay)** | เซิร์ฟเวอร์ของ Tailscale ที่รับผู้เยี่ยมชมจากอินเทอร์เน็ตแล้วพาเข้าสู่ tailnet ของคุณ (ปรากฏเป็น « funnel-ingress-node ») |
| **ผู้ควบคุม (operator)** | บัญชี Linux ที่ได้รับอนุญาตให้ปรับตั้งค่า Tailscale โดยไม่ต้องใช้ sudo (`tailscale set --operator=…`) omega-tail เสนอสิ่งนี้ครั้งเดียวผ่าน sudo |
| **โหนดทางออก (exit node)** | เครื่องใน tailnet ที่เครื่องอื่นส่งทราฟฟิกอินเทอร์เน็ตทั้งหมดผ่าน (เหมือน VPN) ต้องได้รับการอนุมัติในคอนโซลของ Tailscale |
| **ซับเน็ตที่ประกาศ (subnet router)** | เครือข่ายภายใน (เช่น `192.168.1.0/24`) ที่เครื่องหนึ่งทำให้ส่วนอื่นของ tailnet เข้าถึงได้ |
| **โล่ป้องกัน (shields up)** | การตั้งค่าของ Tailscale ที่ปฏิเสธการเชื่อมต่อขาเข้าทั้งหมดที่มาจาก tailnet |
| **SSH ของ Tailscale (Tailscale SSH)** | เซิร์ฟเวอร์ SSH ที่ Tailscale จัดให้ ซึ่งได้รับอนุญาตตามนโยบายของ tailnet |
| **ส่วนหัว PROXY v2** | ส่วนหัวสั้น ๆ ที่เพิ่มไว้ต้นการเชื่อมต่อ เพื่อส่งที่อยู่จริงของผู้เยี่ยมชมให้ฝ่ายที่รับ |
| **ลายนิ้วมือ JA4** | ลายเซ็นของวิธีที่ซอฟต์แวร์หนึ่งเปิดการเชื่อมต่อ TLS: เบราว์เซอร์กับเครื่องมือโจมตีมีลายนิ้วมือไม่เหมือนกัน |
| **AS (ระบบอัตโนมัติ)** | เครือข่ายต้นทางของที่อยู่: ผู้ให้บริการอินเทอร์เน็ต ผู้ให้บริการโฮสติ้ง คลาวด์ |

### เส้นทางของผู้เยี่ยมชม

**Funnel เริ่มต้น ไม่มี omega-tail** `tailscaled` ทำทุกอย่าง: ถอดรหัสอุโมงค์ WireGuard ทำการจับมือ TLS กับผู้เยี่ยมชม
แล้วส่งต่อคำขอเป็น HTTP ไปยังเว็บไซต์ของคุณ ไม่มีไฟร์วอลล์ใดของเครื่องเห็นผู้เยี่ยมชม และการเชื่อมต่อใหม่แต่ละครั้ง
มีต้นทุนสูงสำหรับ `tailscaled`

```text
ผู้เยี่ยมชม ──HTTPS──▶ รีเลย์ Funnel ──WireGuard──▶ tailscaled (TLS + รีเลย์ HTTP) ──HTTP──▶ เว็บไซต์ของคุณ
                   (Tailscale)                └── ต้นทุนทั้งหมดอยู่ที่นี่
```

**Funnel พร้อมประตูของ omega-tail** Funnel เปลี่ยนเป็นโหมด TCP: `tailscaled` ไม่ทำ TLS อีกต่อไป แต่ส่งต่อสตรีมที่ยัง
เข้ารหัสอยู่ไปยังประตู โดยมีที่อยู่จริงของผู้เยี่ยมชมนำหน้า (ส่วนหัว PROXY v2) ประตูตัดสินใจ **ก่อน** การเข้ารหัสใด ๆ:
การเชื่อมต่อที่ถูกปฏิเสธแทบไม่มีต้นทุน และเฉพาะการเชื่อมต่อที่ได้รับอนุญาตเท่านั้นที่ถูกถอดรหัส โดย OpenSSL ซึ่งเร็วกว่า
TLS ของ `tailscaled`

```text
ผู้เยี่ยมชม ──HTTPS──▶ รีเลย์ Funnel ──WireGuard──▶ tailscaled (TCP + PROXY v2)
                                                   │
                                                   ▼
                                    ประตู omega-tail (HAProxy, 127.0.0.1)
                                    ├── ปฏิเสธก่อน TLS: บัญชีดำ, อัตรา, งบประมาณ, ชื่อปลายทาง, การจัดกลุ่ม
                                    └── ยอมรับ: TLS (ใบรับรอง *.ts.net) ──HTTP──▶ เว็บไซต์ของคุณ
```

ประตูรอรับเฉพาะบนลูปแบ็กของเครื่อง และทำงานภายใต้บัญชีของคุณ เครื่องใน tailnet ของคุณได้รับอนุญาตเสมอ ก่อนกฎใด ๆ:
มีเพียงผู้เยี่ยมชมจาก Funnel เท่านั้นที่ถูกกรอง

### สิ่งที่ Tailscale ต้องอนุญาต (คอนโซลผู้ดูแลระบบ)

การตั้งค่าเหล่านี้ทำครั้งเดียวในคอนโซลเว็บของ Tailscale; omega-tail ไม่เปลี่ยนแปลงการตั้งค่าเหล่านี้

- เปิด **MagicDNS** และ **ใบรับรอง HTTPS** ให้ tailnet (จำเป็นสำหรับ Serve, Funnel และใบรับรองของประตู)
- **อนุญาต Funnel** ให้เครื่องในนโยบายการเข้าถึงของ tailnet (แอตทริบิวต์ `funnel`)
- สำหรับโหนดทางออกหรือซับเน็ตที่ประกาศ: **การอนุมัติ** ในคอนโซล

## ฟีเจอร์

เมนูหลักมีสองคอลัมน์ คอลัมน์ละหกรายการ: **TAILSCALE** สำหรับควบคุม และ **การป้องกัน** สำหรับป้องกัน

### TAILSCALE

#### 1. แดชบอร์ด

- **Tailscale**: บริการ สถานะการเชื่อมต่อ เวอร์ชันที่ทำงานอยู่และที่ติดตั้ง ชื่อเครื่อง ที่อยู่ บัญชี อุปกรณ์ที่ออนไลน์
  วันหมดอายุของคีย์ ผู้ควบคุม โหนดทางออกที่เสนอและที่ใช้อยู่ ซับเน็ตที่ประกาศ
- **เครื่อง**: CPU ของทั้งเครื่อง โหลดต่อคอร์ อุณหภูมิ หน่วยความจำ CPU และหน่วยความจำของ `tailscaled` การจำกัด
  ทรัพยากร แล้วตามด้วยสถานะของการป้องกัน (Funnel ไฟร์วอลล์และโหมดโจมตี บัญชีดำ การเฝ้าระวัง โล่ป้องกัน)
- **การเผยแพร่**: แต่ละพอร์ตที่เผยแพร่ สำหรับอินเทอร์เน็ต (Funnel) หรือสำหรับ tailnet (Serve) โหมดและปลายทาง
- **การแจ้งเตือน** จากร้ายแรงที่สุดไปน้อยที่สุด พร้อม « แก้ไข » ที่เปิดหน้าจอที่เกี่ยวข้อง ตัวอย่างเช่น: บริการหยุดอยู่
  ติดตั้งอัปเดตแล้วแต่ยังไม่นำไปใช้ คีย์ใกล้หมดอายุ Funnel เผยแพร่โดยไม่มีการป้องกัน อุณหภูมิสูง `tailscaled`
  ใช้ทรัพยากรมากเกินไปหรือไม่ถูกจำกัด บัญชีดำที่ขยายตัว
- ค่าแสดงเป็นสีเขียว ส้ม หรือแดงตามเกณฑ์ (CPU โหลด อุณหภูมิ หน่วยความจำ `tailscaled`)

#### 2. บริการ tailscaled

- สถานะตามระบบ init เวอร์ชันที่ทำงานอยู่และที่ติดตั้ง คำสั่งเริ่มต้น ไฟล์เสริม (drop-in) การจำกัดทรัพยากร
- **เริ่ม** **หยุด** **รีสตาร์ท** (เช่น เพื่อนำอัปเดตที่ติดตั้งแล้วไปใช้)
- **กลไกป้องกัน**: หากเซสชันของคุณผ่าน Tailscale (SSH ผ่าน tailnet) การหยุดจะขอการยืนยันครั้งที่สอง เพราะคุณจะ
  เริ่มบริการใหม่ไม่ได้อีก
- **แก้ไขการเริ่มต้น**: ตรวจพบไฟล์เสริมที่รัน `tailscale up` ตอนเริ่มระบบ ซึ่งเสี่ยงทำให้เครื่องหลุดออกจาก tailnet
  เมื่อเปลี่ยนการตั้งค่าครั้งแรก; การแก้ไขจะแสดงให้เห็นและเก็บต้นฉบับไว้

#### 3. การเชื่อมต่อและการตั้งค่า

- **เข้าสู่ระบบ** **ออกจากระบบ** **เพิ่มบัญชี** **สลับบัญชี** **ออกจากระบบถาวร** (ต้องพิมพ์ชื่อเครื่อง)
- **ทุกการตั้งค่าของ `tailscale set`** แต่ละรายการมีประโยคอธิบาย: ชื่อและชื่อเล่นของเครื่อง เส้นทาง DNS ของ tailnet
  โล่ป้องกัน การกรองแบบมีสถานะ โหมด netfilter โหนดทางออก การเข้าถึงเครือข่ายภายใน เสนอเครื่องเป็นโหนดทางออก
  ซับเน็ตที่ประกาศ SSH ของ Tailscale อินเทอร์เฟซเว็บ การอัปเดต รีเลย์เพียร์ (peer relay) ผู้ควบคุม
- ระหว่างป้อนค่า กรอบจะแสดง **ก่อน → หลัง** และคำสั่ง; หลังนำไปใช้ แต่ละค่าที่อ่านกลับจะถูกทำเครื่องหมาย ✔
  (มีผลแล้ว) หรือ ✖ (ไม่มีผล)
- คำเตือนจะแจ้งเมื่อการเปลี่ยนแปลงอาจตัดเซสชันที่ผ่าน Tailscale
- **การส่งต่อ IP**: เปิดได้ด้วยปุ่มเดียวเมื่อเครื่องเป็นโหนดทางออกหรือประกาศซับเน็ต

#### 4. การเผยแพร่

- ทุกสิ่งที่เครื่องเผยแพร่: พอร์ต สาธารณะ (Funnel) หรือ tailnet (Serve) โหมด พาธ ปลายทาง การป้องกัน
- **เผยแพร่** บริการภายในเครื่องผ่าน HTTPS, HTTP, TCP หรือ TLS ที่สิ้นสุดที่เครื่อง (TLS-terminated); **ถอน**;
  **พัก Funnel** และ **คืนค่า Funnel** (เหมือนเดิมทุกประการ)
- **ทดสอบแบบต้นทางถึงปลายทาง**: การเชื่อมต่อจริงเหมือนผู้เยี่ยมชม (การตอบกลับ เวลา ใบรับรอง เวอร์ชัน TLS)
- **การสำรอง**: สถานะก่อนการเปลี่ยนแปลงแต่ละครั้ง (50 รายการล่าสุด) กู้คืนได้
- ทุกการเปลี่ยนแปลงถูกตรวจสอบ; หากมีความคลาดเคลื่อน การเผยแพร่จะถูกสร้างใหม่ มิฉะนั้นจะคืนสถานะก่อนหน้า

#### 5. เครือข่ายและอุปกรณ์

- **อุปกรณ์** ใน tailnet: ระบบปฏิบัติการ ออนไลน์หรือไม่ เส้นทาง (ตรงหรือผ่านรีเลย์) เห็นครั้งล่าสุด ที่อยู่ ทราฟฟิก
  ที่แลกเปลี่ยน; รีเลย์ Funnel ของ Tailscale ถูกซ่อนไว้โดยค่าเริ่มต้น
- **Ping ของ Tailscale** (เส้นทางและเวลาแฝง) **นี่คือใคร?** (ที่อยู่ใน tailnet เป็นของใคร)
- **การวินิจฉัยเครือข่าย**: UDP, IPv4 / IPv6 ชนิดของ NAT การเปิดพอร์ตโดยเราเตอร์ (UPnP, NAT-PMP, PCP) รีเลย์ที่ใกล้
  ที่สุดและเวลาแฝง
- **DNS** **การล็อก tailnet (tailnet lock)** และ **ตัวนับภายใน** ของ Tailscale
- อ่านอย่างเดียว: ไม่มีสิ่งใดในหน้าจอนี้เปลี่ยนการตั้งค่า

#### 6. ล็อก

- ล็อกของ `tailscaled` (journalctl หรือไฟล์ของบริการเมื่อไม่ใช้ systemd) และล็อกของประตู กรองได้และส่งออกได้
- ข้อมูลแต่ละส่วนมีสีของตัวเองซึ่งนำมาจากธีม: วันที่ โปรเซส หมวดของข้อความ (การควบคุม เครือข่าย DNS เอนจิน WireGuard)
  ที่อยู่เป็นตัวหนา ข้อผิดพลาดสีแดง คำเตือนสีส้ม; สำหรับประตู: เหตุผลการปฏิเสธ การจัดกลุ่ม AS และประเทศ

### การป้องกัน

#### 7. ไฟร์วอลล์ Funnel

- **ติดตั้ง HAProxy** ด้วยตัวจัดการแพ็กเกจของดิสทริบิวชัน (pacman, apt, dnf, zypper, apk, xbps, emerge)
- **เปิดการป้องกัน**: ใบรับรอง `*.ts.net` รายการต่าง ๆ การกำหนดค่าที่ตรวจสอบแล้ว บริการของประตู การสลับ Funnel
  แล้วทดสอบจากอินเทอร์เน็ต; หากล้มเหลว การเผยแพร่เดิมจะถูกคืนทันที
- **ปิดการป้องกัน**: Funnel ถูกคืนให้เหมือนเดิมทุกประการ พร้อมตรวจสอบ
- **กฎ** ที่นำไปใช้ขณะทำงาน (hot) โหมด **สังเกตการณ์** เพื่อปรับเกณฑ์โดยไม่มีความเสี่ยง **การจัดกลุ่ม** (ดู
  [รายละเอียดของการป้องกัน](#รายละเอียดของการป้องกัน))
- **อัปเดตฐานข้อมูล** AS / ประเทศ (DB-IP Lite) ในโปรเซสแยกต่างหาก

#### 8. การอยู่รอด

- **การจำกัดทรัพยากรของ `tailscaled`**: เพดาน CPU น้ำหนักและลำดับความสำคัญ ตัวเลือกให้ความสำคัญกับการเข้าถึง SSH
- **เบรกเกอร์ Funnel**: เกณฑ์ CPU และอุณหภูมิ ตัด 10 นาที (เปิดกลับอัตโนมัติ) หรือตัดทั้งหมด
- **การเฝ้าระวังอัตโนมัติ**: สิ่งเดียวกันเมื่อไม่มีใครอยู่หน้าจอ
- **โล่ป้องกันพอร์ต WireGuard**: ปุ่มไปยังหน้าจอของมัน (สังเกตการณ์ ใช้งาน วาง วางใหม่ ถอด มอบหมาย)

#### 9. การโจมตีและการตัดสินใจ

- ตัวนับของประตู (ได้รับ ถูกปฏิเสธก่อนการเข้ารหัส ได้รับอนุญาต กำลังดำเนินอยู่) และที่อยู่ที่มีความเคลื่อนไหวมากที่สุด
  อ่านใหม่ทุก 2 วินาที พร้อมประเทศ AS และสถานะของแต่ละที่อยู่
- **บล็อก** **บัญชีดำ** **ปลดบล็อก** **เชื่อถือ**: มีผลทันที โดยไม่ต้องรีสตาร์ทประตู; การแจ้งเตือนบอกในบรรทัดเดียวถึง
  การกระทำและตำแหน่งของที่อยู่
- มุมมอง **ลายนิ้วมือ** **AS** และ **ประเทศ**; สถานะของโหมดโจมตีและการเชื่อมต่อที่ถูกการจัดกลุ่มปฏิเสธ
- **การจัดการบัญชีดำ**: รายการครบถ้วนพร้อมวันที่เพิ่มและที่มา การเพิ่ม การลบ การนำเข้าไฟล์ TXT (ตัดรายการซ้ำ
  เครือข่ายที่ครอบคลุมแล้ว และที่อยู่ของ tailnet ออก) การล้างพร้อมดูตัวอย่าง (ตามอายุ N รายการที่เก่าที่สุด ช่วงบรรทัด
  ที่มาหนึ่งแหล่ง ทั้งหมด) การส่งออก TXT (นำเข้าใหม่ได้) HTML และ JSON เพดาน 50 000 รายการ

#### 10. รายงาน

- ทุกสิ่งที่ omega-tail รู้เกี่ยวกับเครื่อง ในรูปแบบข้อเท็จจริง: Tailscale การเผยแพร่ เครื่อง ไฟร์วอลล์ การอยู่รอด
  การแจ้งเตือน และ **การโจมตีในช่วง 7 วันล่าสุด** ที่อ่านจากล็อกของประตู
- **ความเป็นส่วนตัว**: โดยค่าเริ่มต้น ไม่มีบัญชี Tailscale และไม่มีชื่อหรือที่อยู่ของอุปกรณ์ใน tailnet เพื่อให้ส่งต่อ
  ให้ผู้อื่นได้
- ส่งออก **TXT** **HTML** (เลือกธีมได้) และ **JSON**; **ดูไฟล์ส่งออก** เปิดโฟลเดอร์ในเบราว์เซอร์

#### 11. การตั้งค่า

- ภาษาของอินเทอร์เฟซและการส่งออก ธีมของอินเทอร์เฟซและการส่งออก โฟลเดอร์ของการส่งออกและภาพหน้าจอ และการล้าง
  โฟลเดอร์เหล่านั้น

#### 12. ช่วยเหลือ

## รายละเอียดของการป้องกัน

การป้องกันแต่ละอย่างตอบโจทย์ภัยคุกคามที่เฉพาะเจาะจง; ไม่มีอย่างใดถูกบังคับใช้

| การป้องกัน | ป้องกันอะไร | อยู่ที่ไหน |
|---|---|---|
| ประตู (กฎ) | การยิงถี่ ๆ จากที่อยู่เดียวหรือไม่กี่ที่อยู่ การเชื่อมต่อที่ไม่ได้มุ่งไปยังเว็บไซต์ | ไฟร์วอลล์ Funnel |
| การจัดกลุ่ม | การโจมตีจากที่อยู่กระจัดกระจาย (หลายพันที่อยู่ ที่อยู่ละหนึ่งการเชื่อมต่อ) | ไฟร์วอลล์ Funnel |
| บัญชีดำ | ที่อยู่และเครือข่ายที่ทราบว่าโจมตี เก็บไว้ระยะยาว | การโจมตีและการตัดสินใจ |
| การจำกัดทรัพยากร | `tailscaled` ที่อาจกินทรัพยากรทั้งเครื่องขณะถูกโจมตี | การอยู่รอด |
| เบรกเกอร์ | เครื่องอิ่มตัวทั้งที่มีมาตรการแล้ว: ตัด Funnel ชั่วคราว | การอยู่รอด |
| การเฝ้าระวังอัตโนมัติ | เช่นเดียวกัน เมื่อไม่มีใครอยู่หน้าจอ | การอยู่รอด |
| โล่ป้องกัน WireGuard | กระแสแพ็กเก็ต UDP ท่วมพอร์ตของ `tailscaled` ไม่ว่า Funnel จะเปิดหรือไม่ | การอยู่รอด |

### ประตู (ไฟร์วอลล์ Funnel)

กฎถูกนำไปใช้ตามลำดับนี้ ทั้งหมดก่อนการเข้ารหัส:

1. **เครื่องใน tailnet** (100.64.0.0/10, fd7a:115c:a1e0::/48): ได้รับอนุญาตเสมอ
2. **รายการที่เชื่อถือ**: ไม่ถูกจำกัดเลย **บัญชีดำ**: ถูกปฏิเสธจนกว่าจะถูกนำออก
3. **อัตราต่อที่อยู่** (ค่าเริ่มต้น 40 การเชื่อมต่อ / 10 วินาที): เมื่อเกิน ที่อยู่จะถูกบล็อกตามระยะเวลาที่เลือก
   (ค่าเริ่มต้น 60 นาที)
4. **อัตราต่อพรีฟิกซ์** /24 สำหรับ IPv4, /64 สำหรับ IPv6
5. **งบประมาณรวม** ของการเชื่อมต่อที่ได้รับอนุญาตต่อวินาที: โปรเซสเซอร์ไม่เคยรับภาระเกิน
6. **ชื่อปลายทาง**: การเชื่อมต่อที่ไม่ได้มุ่งไปยังชื่อของเครื่องจะถูกปฏิเสธ

ใบรับรอง `*.ts.net` ของประตูขอจาก Tailscale ตรวจสอบทุกวัน และต่ออายุขณะทำงาน 30 วันก่อนหมดอายุ โหมด
**สังเกตการณ์** นับทุกอย่างโดยไม่ปฏิเสธสิ่งใด

### การจัดกลุ่ม (ลายนิ้วมือ, AS, ประเทศ)

เมื่อเจอการโจมตีจากที่อยู่กระจัดกระจาย กฎตามที่อยู่จะเห็นแต่ละที่อยู่เพียงครั้งเดียว ประตูจึงจัดประเภทไคลเอนต์แต่ละราย
ตาม **ลายนิ้วมือ JA4** **AS** และ **ประเทศ** ด้วย และนับอัตราของแต่ละกลุ่ม

- **โหมดโจมตีอัตโนมัติ**: เมื่อเกิน 80 การเชื่อมต่อขาเข้าต่อวินาที (ปรับได้) ประตูจะเข้าสู่โหมดโจมตีเอง และออกจาก
  โหมดนี้หลังสงบ 5 นาที
- เฉพาะในโหมดโจมตี: ลายนิ้วมือที่ไม่รู้จักซึ่งพุ่งสูงขึ้น AS ของผู้ให้บริการโฮสติ้งหรือคลาวด์ (รายการแก้ไขได้) หรือประเทศ
  ในรายการของคุณ (ว่างโดยค่าเริ่มต้น) ที่เกินอัตราของตนจะถูกปฏิเสธ
- **เบราว์เซอร์ทั่วไป** (Chrome, Edge, Firefox) ไม่เคยได้รับผลจากกฎเหล่านี้; **ไคลเอนต์ที่รู้จัก** (ได้รับอนุญาตภายใน
  24 ชั่วโมงล่าสุด) ได้ผ่านก่อนงบประมาณรวม
- **การเรียนรู้**: ในช่วง 7 วัน ประตูเรียนรู้ลายนิ้วมือที่พบเป็นประจำของเว็บไซต์คุณ (ไม่เคยเรียนรู้ระหว่างการโจมตี);
  จนกว่าจะถึงตอนนั้น การจัดกลุ่มยังอยู่ในโหมดสังเกตการณ์
- นอกช่วงโจมตี จัดประเภทหนึ่งในสิบการเชื่อมต่อ; ระหว่างการโจมตี จัดประเภททั้งหมด
- ฐานข้อมูล AS / ประเทศคือ **DB-IP Lite** ดาวน์โหลดและอัปเดตเดือนละครั้ง

### การอยู่รอด

- **การจำกัดทรัพยากร**: ไฟล์เสริมแยกต่างหากกำหนดเพดานให้ `tailscaled` (เช่น หนึ่งคอร์เต็มบนเครื่อง 4 เธรด) และ
  ลดลำดับความสำคัญของมัน การกำหนดค่าของคุณเองไม่เคยถูกแก้ไข
- **เบรกเกอร์**: เมื่อ `tailscaled` อยู่เหนือเกณฑ์ CPU ต่อเนื่อง (ค่าเริ่มต้น 80 % ของหนึ่งคอร์เป็นเวลา 60 วินาที) หรือ
  อุณหภูมิถึง 85 °C omega-tail เสนอให้ตัด Funnel 10 นาที (เปิดกลับอัตโนมัติ เหมือนเดิมทุกประการ แม้ omega-tail
  ปิดอยู่) ตัดทั้งหมด หรือรอ tailnet ไม่เคยถูกตัด
- **การเฝ้าระวังอัตโนมัติ** (ปิดโดยค่าเริ่มต้น): บริการที่ทำงานภายใต้บัญชีของคุณตัด Funnel เองหลังเกินเกณฑ์สามครั้ง
  ครั้งแรก 15 นาที ครั้งที่สอง 30 นาที จากนั้นหนึ่งชั่วโมง และเปิดกลับเอง

### โล่ป้องกันพอร์ต WireGuard

`tailscaled` ใช้โปรเซสเซอร์ประมาณหนึ่งคอร์ต่อ 100 000 แพ็กเก็ตต่อวินาทีที่ได้รับบนพอร์ต UDP ของมัน แม้แพ็กเก็ต
ไม่ถูกต้องก็ตาม โล่ป้องกันคือตาราง nftables ที่วางไว้หน้ามัน บนการ์ดเครือข่าย:

- **เพียร์ที่รู้จัก** (ที่ `tailscaled` ส่งข้อมูลไปหา) ไม่เคยถูกจำกัด;
- การจับมือถูกจำกัดที่ 20 ครั้งต่อวินาทีต่อแหล่งที่มา;
- แหล่งที่มาอื่นมีงบประมาณ (แหล่งละ 500 แพ็กเก็ตต่อวินาที รวม 5 000);
- แพ็กเก็ตที่ไม่ใช่ WireGuard ถูกปฏิเสธ

ขั้นแรกจะวางในโหมด **สังเกตการณ์** จากนั้นเป็น **ใช้งาน** หากเชื่อมโยงผ่าน omega-connect **omega-fire** (3.7.0
หรือใหม่กว่า) สามารถวางและจัดการแทน omega-tail ได้: เป็นตารางเดียวกันที่เปลี่ยนผู้ดูแลโดยไม่ถูกแตะต้อง

## ผลการวัด

ทางเลือกของ omega-tail มาจากการวัดผล บนเครื่องรุ่นเดียวกับเครื่องที่มันปกป้อง (โปรเซสเซอร์ปี 2010 ถึง 2016
ส่วนใหญ่ไม่มีการเร่ง AES)

| การวัด | ผลลัพธ์ |
|---|---|
| สัดส่วนของ TLS ในต้นทุนการเชื่อมต่อ Funnel เริ่มต้นหนึ่งครั้ง | ประมาณ 80 % |
| ต้นทุนของการเชื่อมต่อที่ **ถูกปฏิเสธ** โดยประตู เทียบกับ Funnel เริ่มต้น | **น้อยกว่า 4.6 เท่า** |
| ต้นทุนของการเชื่อมต่อที่ **ได้รับอนุญาต** โดยประตู เทียบกับ Funnel เริ่มต้น | **น้อยกว่า 2 เท่า** |
| ปริมาณงานเมื่อมีประตู โดยเปิดการเชื่อมต่อค้างไว้ (เทียบกับ TLS ที่เขียนด้วย Go แบบเดียวกับของ `tailscaled`) | คำขอ **+15 %** CPU −20 % |
| โล่ป้องกัน WireGuard: กระแสแพ็กเก็ตที่เคยกินหนึ่งคอร์เต็มของ `tailscaled` | **1 %** ของหนึ่งคอร์ |
| หน่วยความจำของบริการ (ประตู การเฝ้าระวัง โล่ป้องกัน) | ประมาณ 67 MB |

ดังนั้นประตูไม่ได้ทำให้ปริมาณงานของเว็บไซต์ลดลง: บนเครื่องเหล่านี้ การเข้ารหัสเองคือสิ่งที่จำกัด ไม่ว่าจะมีหรือไม่มี
omega-tail และในการใช้งานจริง Funnel ก็ผ่านรีเลย์ของ Tailscale และเราเตอร์อยู่แล้ว

## สถาปัตยกรรม

```text
src/omega_tail/
├── app/              รากของการประกอบ: รวมชั้นต่าง ๆ เข้าด้วยกัน จุดเริ่มต้น (อินเทอร์เฟซ บรรทัดคำสั่ง)
├── core/             ค่าคงที่ที่ใช้ร่วมกัน
├── domain/           ตรรกะทางธุรกิจล้วน: กฎของประตู การแจ้งเตือน เบรกเกอร์ การเฝ้าระวัง บัญชีดำ…
├── application/      กรณีการใช้งาน: การเผยแพร่ ไฟร์วอลล์ การอยู่รอด รายงาน การตั้งค่า
├── ports/            สัญญา (Protocol) ที่ชั้นแอปพลิเคชันต้องการ
├── infrastructure/   Tailscale, HAProxy, nftables, systemd / OpenRC / runit, ล็อก, การส่งออก, สคริปต์ Lua
├── interfaces/       tui/ (Textual), cli/ (บรรทัดคำสั่ง), shared/ (ความช่วยเหลือ รายงาน การนำเสนอ)
└── shared/           ภาษา (gettext)
```

### หลักการออกแบบ

- `domain/` ไม่มีการอ่านหรือเขียนใด ๆ: ทุกอย่างในนั้นทดสอบได้โดยไม่ต้องมีเครื่องจริง
- `application/` ประสานกรณีการใช้งานผ่านโดเมนและพอร์ต; อินเทอร์เฟซและบรรทัดคำสั่งเรียกกรณีการใช้งานชุดเดียวกัน
- มีเพียง `infrastructure.commands` และ `infrastructure.privileged` ที่รันคำสั่ง; อินเทอร์เฟซไม่เคยรันคำสั่งโดยตรง
  กฎเหล่านี้ถูกตรวจสอบโดยอัตโนมัติ (import-linter)
- อินเทอร์เฟซอาศัย [omega-lib](https://github.com/kraynux) ไลบรารีที่ใช้ร่วมกันทั้งชุด OMEGA (ธีม การตรวจหาเทอร์มินัล
  ภาษา ติดต่อและสนับสนุน โล่ป้องกัน WireGuard) ไลบรารีนี้ไม่ได้เผยแพร่บน PyPI: ถูกรวมไว้ในไฟล์เก็บถาวร
  (`vendor/omega-lib/`)
- ทุกการเรียกที่ช้า (Tailscale, HAProxy, ดิสก์, เครือข่าย) ทำงานในเบื้องหลัง: อินเทอร์เฟซไม่เคยค้าง

## ข้อกำหนดเบื้องต้น

### ระบบ

- Linux ทุกดิสทริบิวชัน (ทดสอบบน Arch Linux และดิสทริบิวชันที่สืบทอดมา)
- Python 3.10 ขึ้นไป พร้อมโมดูล `venv`
- ระบบ init: **systemd** **OpenRC** หรือ **runit**
- `sudo` สำหรับการกระทำที่เปลี่ยนแปลงเครื่อง (ขอเป็นรายการกระทำ ไม่เคยขอตอนเปิดใช้งาน)
- เทอร์มินัลขนาดอย่างน้อย 80×24 (ดู [ธีมและเทอร์มินัล](#ธีมและเทอร์มินัล))

### Tailscale

- ติดตั้งและเชื่อมต่อ **Tailscale** แล้ว (ไคลเอนต์ `tailscale` และบริการ `tailscaled`); ทดสอบกับเวอร์ชัน 1.104
- สำหรับ Funnel: อนุญาต MagicDNS ใบรับรอง HTTPS และ Funnel ในคอนโซลของ Tailscale (ดู
  [สิ่งที่ Tailscale ต้องอนุญาต](#สิ่งที่-tailscale-ต้องอนุญาต-คอนโซลผู้ดูแลระบบ))

### การพึ่งพาของ Python

ติดตั้งโดย `install.sh` ในสภาพแวดล้อมเสมือน:

- `textual`: อินเทอร์เฟซ
- `omega-lib`: ไลบรารีที่ใช้ร่วมกันของชุด OMEGA รวมไว้ในไฟล์เก็บถาวร

### ส่วนประกอบที่จำเป็นและที่เป็นตัวเลือก

omega-tail ตรวจหาสิ่งที่มีอยู่และเปิดใช้เฉพาะสิ่งที่ใช้งานได้

| ส่วนประกอบ | บทบาท | สถานะ |
|---|---|---|
| Tailscale (`tailscale`, `tailscaled`) | ทุกสิ่งที่ omega-tail ควบคุม | **จำเป็น** |
| Python 3.10+, `textual`, `omega-lib` | ตัวแอปพลิเคชัน | **จำเป็น** |
| systemd, OpenRC หรือ runit | บริการของประตู การเฝ้าระวัง โล่ป้องกัน | **จำเป็น** (หนึ่งในสาม) |
| HAProxy 3.x | ประตูของไฟร์วอลล์ Funnel | ตัวเลือก (ติดตั้งได้จาก omega-tail) |
| HAProxy ที่มี Lua | การจัดกลุ่ม (ลายนิ้วมือ, AS, ประเทศ) | ตัวเลือก (กรณีของดิสทริบิวชันทั่วไป) |
| nftables (เคอร์เนลที่มี `nft_limit`) | โล่ป้องกันพอร์ต WireGuard | ตัวเลือก |
| สิทธิ์อ่านล็อกระบบ (กลุ่ม `systemd-journal`, `adm` หรือ `wheel`) | ล็อก รายงานการโจมตี | แนะนำ |
| เบราว์เซอร์และเดสก์ท็อป | « ดูไฟล์ส่งออก » ในเบราว์เซอร์ (มิฉะนั้น อ่านใน omega-tail) | ตัวเลือก |
| omega-connect | ทะเบียน การซิงโครไนซ์ การอัปเดตของชุดเครื่องมือ | ตัวเลือก |
| omega-fire 3.7.0+ | จัดการโล่ป้องกัน WireGuard จาก omega-fire | ตัวเลือก |


## การใช้งาน

### การเปิดใช้งาน

```bash
cd ~/omega-tail
./omega-tail.sh

# หรือเพียงแค่ หากสร้าง alias แล้ว:

```

ตัวเปิดใช้งานไม่ขอยกระดับสิทธิ์: omega-tail ทำงานภายใต้บัญชีของคุณ และ sudo จะถูกขอเฉพาะโดยการกระทำที่ต้องใช้
ในเทอร์มินัล พร้อมแสดงคำสั่งก่อน

### ขั้นตอนแรกที่แนะนำ

เพื่อปกป้องเว็บไซต์ที่เผยแพร่ผ่าน Funnel ให้ทำตามลำดับนี้:

1. **แดชบอร์ด**: อ่านการแจ้งเตือน; **เป็นผู้ควบคุม** (ครั้งเดียว ผ่าน sudo) เพื่อปรับตั้งค่า Tailscale โดยไม่ต้องใช้ sudo
2. **การอยู่รอด → ใช้การจำกัดทรัพยากร**: `tailscaled` จะไม่สามารถกินทรัพยากรทั้งเครื่องได้อีก
3. **การเผยแพร่**: เผยแพร่เว็บไซต์ผ่าน **HTTPS บนพอร์ต 443** พาธ `/` แล้วทำ **การทดสอบแบบต้นทางถึงปลายทาง**
4. **ไฟร์วอลล์ Funnel → ติดตั้ง HAProxy** แล้ว **เปิดการป้องกัน** โดยเริ่มในโหมด **สังเกตการณ์**
5. ไม่กี่วันต่อมา **การโจมตีและการตัดสินใจ**: หากตัวนับแสดงเพียงการใช้งานในทางมิชอบ ให้เปลี่ยนประตูเป็น
   โหมด **ปกติ**
6. ปล่อยให้ **การจัดกลุ่ม** เรียนรู้ 7 วันในโหมดสังเกตการณ์ แล้วเปลี่ยนเป็น **บังคับใช้**
7. **การอยู่รอด → โล่ป้องกันพอร์ต WireGuard**: วางในโหมดสังเกตการณ์ แล้วเปลี่ยนเป็นใช้งาน
8. สำหรับเครื่องที่ไม่มีใครอยู่หน้าจอ: **การอยู่รอด → เปิดการเฝ้าระวัง**

### ภาษาของอินเทอร์เฟซ

17 ภาษา: ฝรั่งเศส อังกฤษ สเปน โปรตุเกส (บราซิล) อิตาลี เยอรมัน ดัตช์ โปแลนด์ รัสเซีย จีน เวียดนาม ไทย
อินโดนีเซีย ญี่ปุ่น เกาหลี ฮินดี อาหรับ

- เลือกในการตั้งค่า (ปุ่ม `s`, « Langue / Language » ป้ายที่ไม่เคยแปล) มีผลโดยรีสตาร์ทเฉพาะอินเทอร์เฟซ
- ใช้ครั้งเดียว: `OMEGA_TAIL_LANG=en ./omega-tail.sh`
- ในคอนโซลข้อความของ Linux (TTY) ภาษาที่ตัวอักษรไม่มีในฟอนต์ของคอนโซลจะแสดงเป็นภาษาอังกฤษในเซสชันนั้น;
  ภาษาอาหรับแสดงจากขวาไปซ้าย
- **ภาษาของการส่งออก** (รายงาน บัญชีดำ ล็อก) ตั้งแยกต่างหาก ค่าเริ่มต้นคือ « เหมือนอินเทอร์เฟซ »

### ติดต่อและสนับสนุน

ส่วนช่วยเหลือ (ปุ่ม `a`) มีหน้าจอ **ติดต่อและสนับสนุน**:

- *เลี้ยงกาแฟ* (หน้า PayPal ของนักพัฒนา);
- *ติดต่อฝ่ายสนับสนุน* (ที่อยู่อีเมลและแบบฟอร์มของเว็บไซต์ แสดงอย่างชัดเจน);
- *ลงทะเบียนเป็นผู้ใช้ (นิรนาม)*;
- *ตรวจสอบการอัปเดต*

การลงทะเบียนเป็นไปโดยสมัครใจ ปิดโดยค่าเริ่มต้น และส่งเพียงครั้งเดียว ใช้เพียงเพื่อนับจำนวนผู้ใช้ และหากคุณต้องการ
ก็รวมถึงทวีปหรือประเทศของผู้ใช้ (รายการปิด ไม่เคยเป็นข้อความอิสระ) จะส่งคีย์ที่สุ่มขึ้น ชื่อซอฟต์แวร์ (`omega-tail`)
และเวอร์ชัน ไม่เคยส่งชื่อ ชื่อเครื่อง การตั้งค่า หรือที่อยู่ใน tailnet ถอนได้ทุกเมื่อจากหน้าจอเดียวกัน
(*ไม่ต้องลงทะเบียนฉันอีก*) การตรวจสอบการอัปเดตอ่านเพียงรายการเวอร์ชันที่เผยแพร่บนเว็บไซต์ และไม่เคยทำโดยไม่มีการคลิก

### การเชื่อมโยงกับเครื่องมือ omega อื่น ๆ

- **omega-connect**: `install.sh` เขียนโทเค็นการติดตั้ง (`var/omega-jeton.json`) ที่อธิบายเครื่องมือและเวอร์ชัน
  โดยไม่รันสิ่งใด omega-connect ใช้โทเค็นนี้สำหรับทะเบียน การซิงโครไนซ์ การซ่อมแซม การอัปเดต และการติดตั้ง
  `./omega-tail.sh synchro jeton` เขียนโทเค็นใหม่ด้วยตนเอง

### ลำดับการใช้งานทั่วไป

1. หน้าจอเริ่มต้น แล้วตามด้วยเมนูหลักสองคอลัมน์ (TAILSCALE และ การป้องกัน)
2. ใต้ชื่อของแต่ละหน้าจอ **แถบสถานะ** สรุปทุกอย่าง: บริการ CPU ของเครื่องและของ `tailscaled` อุณหภูมิ หน่วยความจำ
   Funnel ไฟร์วอลล์ การเฝ้าระวัง การเชื่อมต่อ อ่านใหม่ทุก 5 วินาที
3. ทุกการกระทำที่เปลี่ยนแปลงเครื่องจะแสดงคำสั่ง แล้วขอการยืนยัน; sudo ป้อนในเทอร์มินัล จากนั้นอินเทอร์เฟซจะกลับมา
4. การกระทำที่อ่อนไหว (ออกจากระบบถาวร ล้างบัญชีดำทั้งหมด) ต้องพิมพ์คำยืนยัน
5. ผลลัพธ์แสดงในบรรทัดเดียว ตรวจสอบจากสถานะที่อ่านกลับ

- สลับธีมด้วย `t` หรือเลือกธีมจากการตั้งค่า (`s`); ตัวเลือกจะถูกจำไว้

- omega-tail ปรับความซับซ้อนทางภาพให้เข้ากับเทอร์มินัลที่ตรวจพบผ่าน **โปรไฟล์การแสดงผล**: เต็ม มาตรฐาน ลดทอน
  หรือ Mono (ASCII เท่านั้น)

| ขนาดขั้นต่ำ | โปรไฟล์ | เทอร์มินัลทั่วไป |
|---|---|---|
| 120×32 ขึ้นไป | เต็ม | Ghostty, Alacritty, WezTerm, Kitty |
| 100×28 ขึ้นไป | มาตรฐาน | Konsole, GNOME Terminal, Terminator, xfce4-terminal |
| 80×24 ขึ้นไป | ลดทอน | urxvt, xterm, SSH รุ่นใหม่ |
| ต่ำกว่า 80×24 | Mono (ASCII เท่านั้น) | Linux TTY, SSH รุ่นเก่า |

หลังปรับขนาด `r` จะอ่านขนาดเทอร์มินัลใหม่; ขนาดแสดงอยู่ด้านบน ข้างธีม

### บนระบบ (เฉพาะเมื่อคุณเปิดการป้องกันที่เกี่ยวข้อง)

ทุกไฟล์ถูกวางผ่าน sudo โดยแสดงคำสั่ง และถูกถอดออกด้วยการกระทำย้อนกลับใน omega-tail

| ไฟล์หรือบริการ | วางโดย | ถอดโดย |
|---|---|---|
| บริการ `omega-tail-porte` (systemd, OpenRC หรือ runit) และ `omega-tail-porte-certificat` (timer ของ systemd หรือบรรทัดที่ทำเครื่องหมายไว้ใน crontab ของคุณ) | เปิดการป้องกัน | ปิดการป้องกัน |
| `/etc/systemd/system/tailscaled.service.d/50-omega-tail.conf` (หรือกลุ่มควบคุมเมื่อไม่ใช้ systemd) | ใช้การจำกัดทรัพยากร | ถอนการจำกัดทรัพยากร |
| timer `omega-tail-retablir-*` (เปิดกลับหลังการตัด) | เบรกเกอร์ | สิ้นสุดการตัด |
| บริการ `omega-tail-veille` | เปิดการเฝ้าระวัง | ปิดการเฝ้าระวัง |
| บริการ `omega-bouclier-wg`, ตาราง nftables, `/etc/omega-bouclier-wg/` | โล่ป้องกัน: วาง | โล่ป้องกัน: ถอด |
| `/etc/sysctl.d/99-omega-tail-forwarding.conf` | เปิดการส่งต่อ IP | ลบไฟล์ |

ไฟล์ `override.conf` ของ `tailscaled` หากมีอยู่ จะไม่ถูกแก้ไขเลย

### ระบบ init

| | systemd | OpenRC | runit |
|---|---|---|---|
| บริการ `tailscaled` | `systemctl` | `rc-service` | `sv` |
| ล็อก | `journalctl` | ไฟล์ของบริการ | `svlogd`, `socklog` |
| การจำกัดทรัพยากร | ไฟล์เสริมของ systemd | กลุ่มควบคุม (cgroup v2) | กลุ่มควบคุม (cgroup v2) |
| การตัดชั่วคราว | timer ของ systemd | โปรเซสที่แยกตัวภายใต้บัญชีของคุณ | โปรเซสที่แยกตัวภายใต้บัญชีของคุณ |
| ประตู การเฝ้าระวัง โล่ป้องกัน | บริการ systemd | บริการ OpenRC | บริการ runit |

เมื่อไม่ใช้ systemd การจำกัดทรัพยากรด้วยกลุ่มควบคุมจะหายไปหาก `tailscaled` รีสตาร์ท: เมื่อนั้นการแจ้งเตือนจะเสนอให้
ตั้งกลับคืน

### IPv4 และ IPv6

ประตู รายการต่าง ๆ การจัดกลุ่ม และโล่ป้องกันรองรับทั้งสองตระกูลที่อยู่ พรีฟิกซ์ที่นับคือ /24 สำหรับ IPv4 และ /64
สำหรับ IPv6; ที่อยู่ IPv4 ที่ปรากฏในรูป `::ffff:a.b.c.d` จะถูกจัดการเหมือนที่อยู่ IPv4

## ความปลอดภัย

omega-tail ทำงานกับบริการที่เปิดสู่อินเทอร์เน็ต; จึงถูกออกแบบมาเพื่อไม่ทำให้สถานการณ์แย่ลงเลย

- **ไม่เคยเป็น root**: แอปพลิเคชัน ประตู HAProxy และการเฝ้าระวังทำงานภายใต้บัญชีของคุณ; sudo ถูกขอเฉพาะเพื่อวาง
  หรือถอดบริการ โดยแสดงคำสั่งก่อน
- **ช่องทางส่วนตัว**: ซ็อกเก็ตการดูแลของประตูอยู่ในโหมด 600 ภายในโฟลเดอร์ 700; การซิงโครไนซ์ตารางของประตูผ่าน
  ซ็อกเก็ตในโฟลเดอร์เดียวกัน
- **ย้อนกลับได้**: ทุกการสลับ Funnel ถูกสำรองและตรวจสอบ และสถานะก่อนหน้าจะถูกคืนหากล้มเหลว
- **สังเกตการณ์ก่อน**: ประตู การจัดกลุ่ม และโล่ป้องกันถูกวางในโหมดสังเกตการณ์; ไม่มีสิ่งใดถูกปฏิเสธก่อนที่คุณ
  จะตัดสินใจ
- **tailnet ไม่เคยถูกตัด**: ประตูอนุญาตเครื่องของคุณเสมอ และเบรกเกอร์ตัดเฉพาะ Funnel
- **ข้อมูลเข้าที่ผ่านการตรวจสอบ**: มีเพียงที่อยู่หรือเครือข่ายในรูปแบบมาตรฐานเท่านั้นที่ไปถึง HAProxy; ชื่อที่เครื่องใน
  tailnet ประกาศมาจะถูกทำความสะอาดก่อนแสดงผล
- **การตรวจสอบความปลอดภัย**: โค้ดได้รับการตรวจสอบ (claude-security, 2026-11-25); 7 ประเด็นที่พบ ซึ่งไม่มีข้อใด
  ที่ผู้เยี่ยมชมจะใช้โจมตีจากระยะไกลได้ ถูกแก้ไขภายในวันเดียวกัน
- ทดสอบบนเครื่องทดสอบหรือในโหมดสังเกตการณ์ก่อน และใช้เครือข่ายสำหรับเอกสาร RFC 5737 ในการทดสอบ IPv4:
  `192.0.2.0/24`, `198.51.100.0/24`, `203.0.113.0/24`

## สถานะของโปรเจกต์

### ส่วนที่ใช้งานได้

- ควบคุม Tailscale ได้ครบถ้วน: บริการ การเชื่อมต่อ การตั้งค่า การเผยแพร่ เครือข่าย ล็อก
- ประตู HAProxy ก่อน TLS ใช้งานจริงตั้งแต่ 2026-11-23 พร้อมกฎ รายการ การจัดกลุ่ม และโหมดโจมตี
- การอยู่รอด: การจำกัดทรัพยากร เบรกเกอร์ การเฝ้าระวังอัตโนมัติ
- โล่ป้องกันพอร์ต WireGuard ใช้งานจริงตั้งแต่ 2026-11-24
- รายงานและการส่งออก TXT, HTML, JSON
- เข้ากันได้กับ omega-connect และ omega-fire

### ข้อจำกัดที่ทราบ

- บริการภายใต้ OpenRC และ runit ครอบคลุมโดยการทดสอบ แต่ยังไม่ได้ยืนยันบนเครื่องจริง
- ประตูปกป้อง Funnel ที่เผยแพร่ผ่าน HTTPS บนพอร์ตเดียว ด้วยพาธ `/`
- การจัดกลุ่มต้องใช้ HAProxy ที่คอมไพล์พร้อม Lua; หากไม่มี Lua ประตูทำงานได้โดยไม่มีการจัดกลุ่ม
- ไม่สามารถวางโล่ป้องกันบนเคอร์เนลที่อัปเดตแล้วแต่ยังไม่รีบูต (ไม่มีโมดูล): หน้าจอจะแจ้งเรื่องนี้
- การโจมตีที่ทำให้สายอินเทอร์เน็ตเองอิ่มตัวยังอยู่นอกขอบเขตของเครื่องมือที่ติดตั้งบนเครื่อง
- ปริมาณงานของเว็บไซต์ที่เผยแพร่ผ่าน Funnel ยังถูกจำกัดโดยรีเลย์ของ Tailscale และเราเตอร์

## การถอนการติดตั้ง

ขั้นแรก จาก omega-tail ให้ถอดสิ่งที่วางไว้บนระบบออกตามลำดับนี้:

1. **ไฟร์วอลล์ Funnel → ปิดการป้องกัน** (Funnel ถูกคืนเหมือนเดิม)
2. **การอยู่รอด → ปิดการเฝ้าระวัง**
3. **การอยู่รอด → โล่ป้องกันพอร์ต WireGuard → ถอด**
4. **การอยู่รอด → ถอนการจำกัดทรัพยากร**

จากนั้นลบโฟลเดอร์:

```bash
rm -rf ~/omega-tail
```

ลบด้วยตนเอง: ไฟล์ส่งออกที่เก็บไว้ที่อื่น alias `omega-tail` ใน `~/.bashrc` หรือ `~/.zshrc` และหากคุณเคยเปิดใช้
ไฟล์ `/etc/sysctl.d/99-omega-tail-forwarding.conf` สิทธิ์ผู้ควบคุมของ Tailscale ถอนได้ด้วย
`sudo tailscale set --operator=`
